# Milestone A2 – Service runtime

## Built
- CKB-VM sandbox (`runner/src/runtime/`): one VM per run, cycle/memory/wall-time limits (pause mechanism stops tight loops), virtual transaction (witness 0 = payload), CKB syscalls plus service calls 7001–7099 (`spec/host-interface.md`).
- Encrypted per-service KV storage with quotas, `delete_on_consume` and `csr storage simulate-consumed` (`runner/src/storage/`).
- Service signing with domain separation (syscall 7020).
- Example services in Rust (`services/rust/`), C (`services/c/hello`) and JavaScript on ckb-js-vm (`services/js/hello`), manifests in `services/manifests/`, `scripts/build-services.sh`.
- Local registry (SQLite), CLI `csr service add-local|list|approve|revoke|enable|disable`, `GET /api/services`, `POST /api/services/{code_hash}/{approve|revoke|enable|disable}` and the dashboard page **Services** (`#/services`).

## Demo
```
bash scripts/build-services.sh
csr service run-local --manifest services/manifests/hello-rust.toml --payload 0x010203
csr service add-local --manifest services/manifests/hello-rust.toml
csr service list --json
csr service approve 0x<code_hash>
csr run        # then open http://127.0.0.1:8130/#/services
```

## Limits found
- ckb-vm has a fixed 4 MiB memory; only `max_vm_memory_mb = 4` is accepted.
- JS services cannot issue custom syscalls; results go through the `CSR-RESULT:` debug fallback (≤ 505 bytes).
- `jobs` and `earned_shannons` stay 0 and chain calls (7003/7004) return 2 until A3.
- A running `csr run` does not see `allowed_services` changes made by the CLI until restart.
- See `docs/decisions.md` for details.
