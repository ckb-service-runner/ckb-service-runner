# Milestone A1 – Runner, guard, dashboard, ping responder

## What was built

- CLI: `version`, `config validate`, `check`, `detect`, `set-password`, `run`.
- Config model with strict validation (unknown keys rejected), per-network data directories, key generation (`service.key`, `storage.key`, mode 0600).
- Node RPC client (plain JSON-RPC over HTTP) and the R2 guard (Unknown / Unreachable / Degraded / Syncing / Synced), run every 10 s.
- Resource monitor with samples stored in SQLite (24 h history).
- Embedded dashboard (`runner/assets/`, ≤ 200 KB, no external URLs) and JSON API with SSE.
- Auth: argon2id password, sessions (`csr_session` cookie), CSRF token on all writes, settings API with atomic save and `.bak`.
- Ping protocol v1: inbound `POST /v1/challenge` (rate limit, replay protection) and outbound check-in (`/v1/checkin` → `/v1/answer`).
- Tests: Rust unit and integration tests (`runner/tests/`, including the Rust mock monitor in `runner/tests/mock_monitor/`) and the acceptance suite in `acceptance/a1/`.

## How to demo

1. `cargo build` and point `[node] rpc_url` at a synced testnet node (or run the integration tests, which use mock nodes).
2. `csr detect`, then `csr check` – exit code 0 means Synced.
3. `csr run`, open `http://127.0.0.1:8130/`, look at Overview/Node/Resources, change a setting.
4. Ping: with `ping_mode = "inbound"`, `POST` a monitor-signed challenge to `127.0.0.1:8131/v1/challenge`; with `outbound`, watch `last_check_ok_at` in `/api/status` after a check-in.
5. Fast demo of the loops: debug build with `CSR_TEST_FAST_TICK=1` (R2 and resources every 1 s, check-ins every 2 s).

## Known limits

- The real monitor does not exist: URL `https://monitor.invalid` and the secp256k1 generator point as public key are placeholders. Ranking cannot work against a real monitor yet.
- `mainnet_runtime_unlocked()` is always false; the runtime stays `inactive` on mainnet. No jobs or services exist yet.
- The binding proves peer ID ↔ service key by the service key's signature only; the node's P2P key does not sign it (see open questions).
- Neuron nodes are accepted via `node_type = "neuron"`, but their RPC port and indexer availability are unverified.
- Outbound check-ins use the monitor's plain HTTP reply; no retries within an interval.
- The dashboard has no TLS; use a reverse proxy for remote access.
